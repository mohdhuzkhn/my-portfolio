<h2 id="architecture">Architecture decisions</h2>

Choose the simplest reliable method that meets the requirement. Rules and SQL are strong starting points for structured tasks. Introduce retrieval, predictive models, or generative AI when the problem calls for them.

<div className="my-6 space-y-4">
  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Exact calculations and permissions</h3>
    <p className="!mb-0">
      Use deterministic application code or SQL for fee totals, eligibility
      checks, and permission decisions. An LLM is usually unnecessary.
    </p>
  </div>
  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Field mapping and API synchronization</h3>
    <p className="!mb-0">
      Use schema mapping, validation, and retries. Consider an LLM only when
      inconsistent free-text input requires interpretation.
    </p>
  </div>
  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Facts in approved documents</h3>
    <p className="!mb-0">
      Start with search, filtered SQL, or keyword retrieval. Add
      evidence-grounded natural-language synthesis when it helps the user.
    </p>
  </div>
  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Variable emails and unstructured notes</h3>
    <p className="!mb-0">
      Extract into a defined JSON schema, validate the result, and route
      uncertain cases for review.
    </p>
  </div>
  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Messages and business-record changes</h3>
    <p className="!mb-0">
      Use authorized API calls with audits and approval gates. A model may
      propose an action, while policy determines whether execution is allowed.
    </p>
  </div>
</div>

Before selecting a model, ask whether the input is structured, the answer is exactly computable, an error is reversible, or a side effect is involved. Identify the decisions that require an authorized human.

### Reference system

<ol className="space-y-3">
  <li>Channels, CRM, ERP, and legacy databases provide inputs.</li>
  <li>
    An authenticated FastAPI gateway establishes the caller and request
    contract.
  </li>
  <li>
    A policy and workflow router selects rules, SQL, search, or bounded LLM
    extraction.
  </li>
  <li>
    A validated tool adapter checks the proposed operation and its parameters.
  </li>
  <li>Approval gates control sensitive writes to systems of record.</li>
</ol>

Support the flow with PostgreSQL state and audit logs, queues and workers, a secret manager, tenant-aware RBAC, traces and metrics, offline and online evaluations, monitoring, and incident runbooks.

<h2 id="evaluation">Evaluation gates</h2>

Define release criteria before building the pilot. The following values are **illustrative starting targets**, not universal production standards. Adjust them to the workflow's risk and validate with an appropriate sample.

  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Tool-action authorization</h3>
    <p className="!mb-0">
      100% compliance on the test suite. Block release on any violation.
    </p>
  </div>
  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Required structured fields</h3>
    <p className="!mb-0">
      At least 98% exact match on the curated evaluation set.
    </p>
  </div>
  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Grounded answer correctness</h3>
    <p className="!mb-0">At least 90% on evaluated, in-scope questions.</p>
  </div>
  <div className="rounded-[var(--radius-m)] border border-line p-5">
    <h3 className="!mt-0">Escalation and abstention</h3>
    <p className="!mb-0">
      At least 95% on known unanswerable or sensitive cases.
    </p>
  </div>
</div>

Measure p50/p95 latency and cost per task against the SLA and business case. High-impact workflows may require stricter controls and larger validation samples. Passing a curated test set alone does not establish production safety.

<h2 id="discovery">Discovery and ROI</h2>

### Questions for the discovery sprint

- What triggers the workflow, and which system is the source of truth?
- How many cases occur each week? What are handling time, rework, and error rates?
- Which exceptions require an authorized human decision?
- Which departments, tools, data classifications, and third-party vendors are involved?
- What minimum improvement would make deployment worthwhile?

### Establish the baseline first

Use a representative sample. Include human review, correction, integration, and model costs in the pilot assessment.

<div className="my-6 space-y-4 rounded-[var(--radius-m)] border border-line bg-surface p-5">
  <p>
    <strong>Monthly hours saved</strong>
    <br />
    Eligible monthly tasks × (baseline minutes per task − post-pilot human
    minutes per task) ÷ 60.
  </p>
  <p>
    <strong>Monthly net benefit</strong>
    <br />
    Verified labor or capacity value + avoided error cost − AI, infrastructure,
    supervision, and support costs.
  </p>
  <p className="!mb-0">
    <strong>Pilot ROI (%)</strong>
    <br />
    (Net operating benefit over the evaluation horizon − one-time implementation
    cost) ÷ one-time implementation cost × 100.
  </p>
</div>

Show assumptions and the evaluation horizon explicitly. When labor is redeployed rather than eliminated, report **capacity released**, rather than claiming cash savings. If implementation cost is zero, report net benefit instead of dividing by zero.

- **Scale:** Quality and safety gates pass, value is positive, and a stakeholder owns the process.
- **Revise:** Quality or adoption gaps are tractable. Define another limited test with clear criteria.
- **Stop:** A safety violation, unreliable system of record, absent owner, or negative economics prevents responsible expansion.

<h2 id="stack">Recommended stack</h2>

### Master first

Python, FastAPI, PostgreSQL, pytest, Git and GitHub Actions, and Docker. Develop depth in structured outputs, tool calling, OAuth, JSON Schema, and RBAC.

### Add when the workflow needs it

LangGraph, pgvector or Qdrant, Redis or RabbitMQ, OpenTelemetry, and LangSmith or Phoenix. Learn hybrid retrieval, rerankers, MCP, and managed cloud deployment as the requirements become concrete.

### Recognize before specializing

CrewAI and AutoGen alternatives, Kafka, Kubernetes, vendor-specific SAP or NetSuite features, knowledge graphs, multi-cloud orchestration, and specialized fine-tuning.

Build one solid implementation per necessary category before spreading effort across competing frameworks. Add infrastructure because of demonstrated requirements, rather than a checklist of tools.

<h2 id="evidence">Portfolio evidence</h2>

Prepare a dossier that lets another engineer or stakeholder inspect the pilot's behavior and limits.

- **Case study:** One page covering the customer problem, baseline, architecture, deployment scope, measured results, and limitations.
- **Public sample repository:** Synthetic data, a clear README, architecture diagram, `.env.example`, Docker configuration, migrations, tests, and CI.
- **Evaluation record:** Dataset provenance, scoring rubric, baseline/candidate comparison, failed cases, and mitigations.
- **Operations record:** Threat model, access design, monitoring dashboard, incident and rollback procedures, and retention policy.
- **Executive demo:** A three-minute workflow walkthrough and a one-slide ROI decision. Protect client information by using synthetic or properly anonymized examples.

### Readiness checkpoints

1. **Foundation:** A webhook-driven service survives retries and invalid inputs without corrupting data.
2. **Agent design:** Tool use obeys permissions, produces schema-valid outputs, and can abstain.
3. **Evaluation:** Model or prompt changes run against saved datasets and regression thresholds.
4. **Operations:** Logs, traces, access controls, rollback, and human approvals work together.
5. **FDE delivery:** Stakeholders agree on the baseline, success criteria, measured benefit, and ongoing owner.

### Interpret the guide carefully

The suggested 12–16 weeks is a planning estimate, not a guaranteed time to mastery. Adapt the route to your existing skills, budget, access, and engagement risks.

Broad claims that “95% of GenAI pilots fail” are not used as verified facts here. Failure rates depend on definitions and study design.

An LLM judge is an imperfect quality proxy. Calibrate it with human labels and avoid treating it as the sole authority for consequential decisions. Confidence thresholds also require calibration: combine evidence sufficiency, rule-based signals, and human-review routing.

Logging complete prompts may conflict with privacy requirements. Apply redaction, access controls, defined retention periods, and auditable metadata.

Compliance obligations differ by geography and data type. This guide is an engineering starting point, not compliance certification.
